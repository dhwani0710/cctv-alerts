4. BUGFIX — GENERIC FORM FIELD STYLES RESTORED (css/styles.css)
============================================================
Issue: When the old login CSS block was removed in step 3, it
accidentally took the generic .field / .field label / .field input
rules with it. Those rules are shared by every form in the app —
not just login — so the "Add employee" form (AdminEmployees.jsx)
lost its styling (label and input rendered inline instead of
stacked, no border/padding).

Fix: Re-added a standalone generic form-field block:
  .field{ margin-bottom:16px; }
  .field label{ display:block; font-size:12px; font-weight:600;
    margin-bottom:6px; color:var(--text-muted); letter-spacing:.02em; }
  .field input, .field select{ width:100%; padding:11px 13px;
    border-radius:var(--radius-md); border:1px solid var(--border);
    background:var(--surface); font-size:14px; font-family:var(--font-body);
    color:var(--text); }
  .field input:focus, .field select:focus{ outline:none;
    border-color:var(--brass); box-shadow:0 0 0 3px var(--brass-glow); }

This block is placed BEFORE the login-page CSS section. The more
specific .login-card .field rules further down still override it
correctly inside the dark login card only, so:
  - Login form  → keeps dark eSamyak styling
  - Every other form (Add employee, filters, etc.) → back to
    normal light-theme field styling
